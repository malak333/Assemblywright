# Developer GitHub restoration

The Developer GitHub setup and publication feature was recovered from the original
approved conversation and retained source archive, rather than recreated from the
later GitHub-link placeholder. The five recorded archive fingerprints match the
retained original source. The standalone publication, process-containment, setup,
settings and catalog files were recovered byte-for-byte; Swift setup and publication
views were recovered from successful original session edits.

The restored workflow signs in through the Windows GitHub account, lists accessible
repositories, explicitly creates a repository when requested, and connects a project
to a protected destination. Future approved features use their own branch and pull
request, then merge after exact-commit required checks pass. Historical local-only
features are not implicitly published. The two accepted GitHub design documents
remain the behavior contract.

Integration preserves the later grouped-chat migration, exact repair provenance,
planning-completion recovery, cloud redaction, and effective Emergency Pause latch.
Supporting model selections bind the actual planner/reviewer invocation, response
and UI status to the selected model and reasoning level. This restoration does not
replace the independent Settings interface.

Review corrections keep Stop available during setup and reconciliation, preserve
durable success after a late Stop, prevent rejected shutdown from cancelling active
publication, and release runtime ownership even if attention persistence fails.
Changing the connection destination cannot strand unresolved GitHub work; rebuilding
the same destination retains its durable recovery state and tool configuration.
